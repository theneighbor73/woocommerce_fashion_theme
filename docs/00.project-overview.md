# Project Overview

## Purpose

Alice is a reusable WordPress Block Theme for fashion stores using WooCommerce. Its visual direction is minimalist contemporary fashion with a lifestyle-editorial feel: strong typography, generous whitespace, expressive photography, and clear shopping layouts.

## Non-negotiable scope

This is theme development only. The theme presents content and native WordPress/WooCommerce functionality; it does not own business behavior or persistent business data.

- Use native WordPress and WooCommerce features for content, navigation, products, variations, search, cart, checkout, accounts, payments, shipping, and orders.
- Do not create custom blocks, post types, taxonomies, tables, shortcodes, commerce logic, or external-service integrations.
- Use block templates, template parts, patterns, `theme.json`, and CSS for presentation. Use the Interactivity API only for progressive visual interactions, such as menu state. It must not replace or extend shopping behavior.
- If a requirement falls outside this scope, stop and present the native fallback and any existing-plugin option. The project owner chooses whether to use the fallback, defer the requirement, or add it to [the Custom Block Consideration List](consideration-list.md). Do not proceed without that decision.
- Do not add newsletter signup, cookie management, or other service/business functionality. Content may link to merchant-managed pages or services.

## WooCommerce dependency

WooCommerce is required for the intended ecommerce storefront. If it is inactive, the theme must avoid fatal errors, render general WordPress content, and give administrators an appropriate notice that WooCommerce is needed for store features.

## Layout and merchant editing

Layouts have fixed composition: the theme controls where elements sit in relation to one another. Merchants may edit intended content, media, logo, and navigation items/structure through native WordPress tools. For example, navigation contents can change while the header keeps its specified logo/menu arrangement. Use `contentOnly` locking where it supports this model; document justified exceptions in the relevant UI specification.

## Visual direction and palette

Keep the design premium but approachable, editorial rather than generic, and usable across mobile, tablet, and desktop. Prefer purposeful imagery and whitespace over decoration.

Use this six-role palette as the current fixed baseline; do not add or substitute palette roles without the project owner's direction:

| Role | Value | Use |
|---|---|---|
| Dark surface / primary | `#111111` | Header, primary buttons, footer, high-contrast text |
| Canvas | `#F9F8F6` | Page and subtle section backgrounds |
| Brand accent | `#C5A059` | Sale and selected states, promotional emphasis |
| Body text | `#222222` | Paragraphs and supporting headings |
| Borders | `#E5E5E5` | Dividers and form boundaries |
| Feedback / alert | `#C62828` | Errors and critical notices |

Token names and mappings belong in [UI Tokens](frontend/08.ui-tokens.md). Other visual values (type, spacing, and layout) are defined there when approved.

## Development environment

These are local development environment versions, not a minimum support contract:

| Component | Local version |
|---|---|
| WordPress | 7.1.4 |
| WooCommerce | 10.8.1 |
| PHP | 8.3.30 |

Theme name: **Alice**. Theme slug: **`alice-theme`**. Use the slug for WordPress handles and text domain; use a valid underscore form such as `alice_theme_` for PHP identifiers. The repository is the source of truth for theme structure.
