# Project Overview

## Purpose

Alice is a reusable WordPress Block Theme for fashion stores using WooCommerce. See [Design Foundations](frontend/design-system-reference.html) for the shared visual direction and [UI Tokens](frontend/08.ui-tokens.md) for approved values and token roles.

## Non-negotiable scope

This is theme development only. The theme presents content and native WordPress/WooCommerce functionality; it does not own business behavior or persistent business data.

- Use native WordPress and WooCommerce features for content, navigation, products, variations, search, cart, checkout, accounts, payments, shipping, and orders.
- Do not create custom blocks, post types, taxonomies, tables, shortcodes, commerce logic, or external-service integrations.
- Use block templates, template parts, patterns, `theme.json`, and CSS for presentation. Use the Interactivity API only for progressive visual interactions that native blocks and CSS cannot provide, such as menu state and scroll-driven hero slides. It must not replace or extend shopping behavior.
- Treat portability as a design principle: make recurring merchant-facing sections from native blocks and expose them as inserter patterns, then reuse those patterns in templates instead of duplicating their block markup. Pattern insertions are independent editable copies; use template parts for shared structural regions. Do not create custom blocks just to package reusable presentation.
- If a requirement falls outside this scope, stop and present the native fallback and any existing-plugin option. The project owner chooses whether to use the fallback, defer the requirement, or add it to [the Custom Block Consideration List](consideration-list.md). Do not proceed without that decision.
- Do not add newsletter signup, cookie management, or other service/business functionality. Content may link to merchant-managed pages or services.

## WooCommerce dependency

WooCommerce is required for the intended ecommerce storefront. If it is inactive, the theme must avoid fatal errors, render general WordPress content, and give administrators an appropriate notice that WooCommerce is needed for store features.

## Default activation experience

The theme supplies a prebuilt `front-page.html` composition using native blocks, including editorial content and a WooCommerce product collection. Do not create or seed WordPress pages, products, or other database content on activation. The merchant can edit the intended text and media through native editor tools; the product collection uses the store's existing catalog and should remain presentable when that catalog is empty.

## Compatibility baseline

For initial implementation and compatibility checks, the local environment versions below are also the minimum platform versions:

| Component | Local version and minimum |
|---|---|
| WordPress | 7.1.4 |
| WooCommerce | 10.8.1 |
| PHP | 8.3.30 |

Support the current and previous major versions of Chrome, Edge, Firefox, and Safari, including iOS Safari. Avoid relying on features unavailable in that browser range without a graceful fallback.

## Layout and merchant editing

Templates and patterns have fixed composition while intended content remains editable through native WordPress tools. Define editing and locking behavior in the relevant UI Registry entry; use `contentOnly` locking where it supports this model and document justified exceptions there.

During theme development, the agent may write clearly replaceable sample copy anywhere in theme templates, including taglines, addresses, and contact details. Use unmistakable placeholder details such as `Example Street` and `example.com`; do not present invented business information as verified merchant facts. Keep the copy editable through native WordPress blocks.

## Visual direction

The shared visual direction is minimalist, contemporary fashion with a lifestyle-editorial feel. See [Design Foundations](frontend/design-system-reference.html) for principles and [UI Tokens](frontend/08.ui-tokens.md) for the sole source of approved color roles, values, and other design tokens.

## Theme identity

Theme name: **Alice**. Theme slug: **`alice-theme`**. Use the slug for WordPress handles and text domain; use a valid underscore form such as `alice_theme_` for PHP identifiers. The repository is the source of truth for theme structure.
