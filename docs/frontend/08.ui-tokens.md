# UI Tokens

This document defines Alice’s design values and token relationships. The [Design Foundations](design-system-reference.html) page is the visual companion. The [UI Registry](09.ui-registry.md) specifies page, template, and component presentation. This foundation uses Material 3 token naming; component tokens remain out of scope until components are specified.

## Token architecture and naming

Material token names have the form `md.<tier>.<category>.<role>[-<variant>]-<attribute>`. The CSS custom-property form uses `--md-` and hyphens, for example `md.sys.color.primary` becomes `--md-sys-color-primary`.

| Tier | Purpose | Alice examples |
| --- | --- | --- |
| Reference (`md.ref`) | Concrete palette and typeface choices | `--md-ref-palette-alice-neutral-ink`, `--md-ref-typeface-brand` |
| System (`md.sys`) | Semantic roles and shared scales | `--md-sys-color-primary`, `--md-sys-shape-corner-medium`, `--md-sys-typescale-body-medium-size` |
| Component (`md.comp`) | Component-specific choices | Deferred until component specifications are addressed |

Alice reference palette names use Material’s `md.ref.palette` tier and a project-specific `alice` palette namespace. Descriptive names are intentional: Alice’s curated source colors are not generated Material tonal palettes, so numeric Material tone labels would misrepresent them. Alice-specific layout and spacing extensions use the same `md.sys` namespace and are identified as project extensions below.

Reference values are the ingredients; system tokens describe what they do. Prefer system roles in future styles. Add component tokens only when a component needs an independent value.

### CSS source of truth and layers

`assets/css/variables.css` is the single source of truth for concrete reference values. Define all raw/base reference tokens there, including project-specific primitives needed by Alice system extensions. `theme.css` and downstream system/component token layers must alias those references; they must not repeat raw reference values. CSS, JavaScript, and PHP consumers use the canonical `--md-ref-*` and `--md-sys-*` names documented here. Do not introduce parallel short-name token namespaces.

An underlying concrete value may be represented by a descriptive Alice reference token even when its system role is a project extension. Keep the system token semantic and map it to the reference token. Preserve WordPress presets in `theme.json` for merchant-facing block controls; CSS token values in this architecture resolve through the canonical tokens rather than WordPress preset fallbacks.

Alice system extensions retain existing component dimensions, borders, shadows, and layer roles when no direct Material system role exists. These include the `--md-sys-control-*`, `--md-sys-layout-alice-content-cap`, `--md-sys-color-alice-brand-accent`, `--md-sys-border-width-*`, `--md-sys-elevation-shadow-*`, and `--md-sys-layer-dropdown` roles. Typography uses the complete documented Material type styles; each consumed style defines its font, size, line height, weight, and tracking. Their concrete reference values live under matching descriptive `--md-ref-alice-*` primitives in `variables.css`. The existing `3px` control radius is exposed as `--md-sys-shape-corner-alice-small`; it remains separate from Material’s standard corner scale.

| Alice system extension | Reference values in `variables.css` | Retained value |
| --- | --- | --- |
| `--md-sys-color-alice-brand-accent` | `--md-ref-palette-alice-brand-gold` | `#C5A059` |
| `--md-sys-color-success` | `--md-ref-palette-alice-success` | `#2F6B45` |
| `--md-sys-space-*` | `--md-ref-alice-space-*` | Existing spacing scale, including `0.75rem` compact spacing |
| `--md-sys-layout-alice-content-cap` | `--md-ref-alice-layout-content-max` | `47.5rem` legacy content cap |
| `--md-sys-control-*`, `--md-sys-media-product-ratio` | Corresponding `--md-ref-alice-control-*`, `button/input-padding-*`, and `media-product-ratio` references | `3rem`, `2.375rem`, `1.75rem`, `1rem`, and `3 / 4` |
| `--md-sys-shape-corner-alice-small`, `--md-sys-border-width-*` | Corresponding `--md-ref-alice-shape-*` and `border-width-*` references | `3px`, `1px`, and `2px` |
| `--md-sys-elevation-shadow-*`, `--md-sys-layer-*`, `--md-sys-motion-*` | Corresponding `--md-ref-alice-shadow-*`, `layer-*`, and `motion-*` references | Existing shadow, layer, and timing values |

Success remains an Alice semantic extension if native feedback needs it.

### Contrast requirements

- Meet WCAG 2.2 AA for text and theme-authored UI. Verify every actual foreground/background pairing; do not infer a pass from a token name.
- Normal text requires at least 4.5:1 contrast; large text requires at least 3:1. Meaningful non-text boundaries and focus indicators require at least 3:1 against adjacent colors.
- Gold `#C5A059` is approximately 2.3:1 against the canvas and is unsuitable for small text there. Reserve it for decorative emphasis on that background.
- Quiet border `#E5E5E5` is not sufficient for every essential boundary. Use the stronger outline role `#666666` when a boundary communicates control or state.
- Status meaning must include text, shape, or another perceivable cue; color alone is insufficient.

## Typography

### Reference typefaces

Material reference typeface tokens are `brand` and `plain`; Alice assigns its existing families to those purposes.

| Reference token | Value / source | Intended voice |
| --- | --- | --- |
| `--md-ref-typeface-brand` | `"Cormorant Garamond", Georgia, serif` · bundled variable family | Editorial display and expressive headings |
| `--md-ref-typeface-plain` | `"Plus Jakarta Sans", -apple-system, BlinkMacSystemFont, sans-serif` · bundled variable family | Reading, product information, navigation, and controls |

Keep the existing local font assets and their OFL license files. Do not introduce another family to imitate Material samples.

### System type scale

Use Material’s scale of five roles at three sizes: display, headline, title, body, and label; large, medium, and small. The figures below are the baseline Material scale in CSS pixels, expressed in `rem` at a 16px root size. Font families are Alice’s brand/plain assignment; line-height, weight, and tracking follow the baseline values. Alice adopts emphasized weight variants for title and label only. These preserve each baseline style’s family, size, line-height, and tracking; only weight changes.

| --- | --- | --- | --- | --- |

| `--md-sys-typescale-headline` | Brand | `2rem / 2.5rem / 400 / 0` | `1.75rem / 2.25rem / 400 / 0` | `1.5rem / 2rem / 400 / 0` |
| `--md-sys-typescale-title` | Plain | `1.375rem / 1.75rem / 400 / 0` | `1rem / 1.5rem / 500 / 0.009375rem` | `0.875rem / 1.25rem / 500 / 0.00625rem` |
| `--md-sys-typescale-body` | Plain | `1rem / 1.5rem / 400 / 0.03125rem` | `0.875rem / 1.25rem / 400 / 0.015625rem` | `0.75rem / 1rem / 400 / 0.025rem` |

Each style expands to Material’s `<role>-<size>` token attributes: `font`, `size`, `line-height`, `weight`, and `tracking`, for example `--md-sys-typescale-body-medium-size`. Use display for short, high-impact text; headline for page hierarchy; title for shorter medium-emphasis text; body for reading; and label for brief utility text. Keep Alice’s serif/sans assignment while checking line wrapping, font metrics, and readability in the HTML reference before implementation. Do not use label styles for extended reading.

### Emphasized type styles

Alice uses emphasized styles for title and label only, to strengthen selected hierarchy and brief, attention-worthy text while preserving baseline metrics. The emphasized token naming below follows Material’s role/size vocabulary with an Alice extension: Material’s web token set does not define this separate emphasized suffix. `--md-sys-typescale-<role>-<size>-emphasized-weight` is the only changed attribute; all other attributes alias the corresponding baseline token. Display, headline, and body retain baseline styles only.

| Role | Large baseline → emphasized | Medium baseline → emphasized | Small baseline → emphasized |
| --- | --- | --- | --- |
| Title | `400 → 500` | `500 → 700` | `500 → 700` |
| Label | `500 → 700` | `500 → 700` | `500 → 700` |

Examples: `--md-sys-typescale-title-medium-emphasized-weight: 700` and `--md-sys-typescale-label-large-emphasized-weight: 700`; other attributes resolve to the matching baseline `--md-sys-typescale-<role>-<size>-*` tokens. Keep ordinary reading and dense utility text at baseline weight unless emphasis improves scanning without reducing legibility.

| `--md-sys-layout-margin` / `--md-sys-layout-gutter` | Current width-class value from the corresponding compact/medium/expanded token |

The former mobile/tablet/desktop/wide ranges and `--md-sys-layout-content-max`, `--md-sys-layout-wide-max`, and single responsive `--md-sys-layout-gutter` values are superseded by this taxonomy. Use the current-class margin/gutter roles and the independent prose/container rulers above.

| --- | ---: | --- |

Do not add a bottom navigation bar or navigation rail.

At compact width and on short landscape viewports (`height < 480px`), cap a sticky top bar at `20svh` and allow its contents to scroll within it; at 200% text zoom, no header content may be clipped and the bar must leave the remaining viewport available to the page.

### Reflow, containment, and exceptions

- At a `320px` viewport, page-level horizontal overflow is zero. Put any wide data or pill strip in an isolated, keyboard-accessible horizontal scroll container with a visible focus indicator and clear accessible name; do not let it widen the page.
- Use intrinsic sizing and wrapping, including `minmax(min(100%, …), 1fr)`, `min(100%, …)`, and `flex-wrap`. Ensure grid/flex children can shrink (`min-width: 0`) and media fit their containers.
- Standard templates and pervasive components obey the class margins, grid, and spacing tokens. Only high-impact merchandising may break out to `100vw`; its inner text and actions remain aligned to the grid margin ruler.
- A bespoke hero/editorial section may define local spatial properties. Standardized components and templates may not.
- Keep product card actions aligned across each grid row. Do not set fixed card heights to force alignment.

WCAG 2.2 SC 1.4.10 requires vertical-reading content to reflow at 320 CSS pixels, with exceptions for content whose two-dimensional layout is essential. Alice’s zero-page-overflow rule is the stricter system default; isolated horizontal regions must remain usable without page-level overflow.

References: [Material window size classes](https://developer.android.com/develop/ui/views/layout/use-window-size-classes) and [WCAG 2.2 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow).

## Elevation, shadow, and scrim

Material elevation levels describe distance along the z-axis; they do not themselves specify a shadow blur recipe. On the web, use the CSS pixel equivalents below as the foundation. Keep the number of elevation levels used in a design small.

| System token | Elevation | Use |
| --- | --- | --- |
| `--md-sys-elevation-level0` | `0px` | Resting surface |
| `--md-sys-elevation-level1` | `1px` | Minimal lift |
| `--md-sys-elevation-level2` | `3px` | Low lift |
| `--md-sys-elevation-level3` | `6px` | Medium lift |
| `--md-sys-elevation-level4` | `8px` | High lift |
| `--md-sys-elevation-level5` | `12px` | Highest shared lift |
| `--md-sys-color-shadow` | `#111111` | Shadow color for a rendered elevation treatment |
| `--md-sys-color-scrim` | `#111111` | Translucent color that dims the backdrop beneath an overlay |

Use shadow where a floating layer needs separation; keep ordinary content flat. Use scrim to reduce the visual prominence of content behind an overlay. Scrim opacity and overlay geometry are context-specific and belong to the relevant component specification. The scaffold layer tokens above are Alice stacking-order extensions, not Material elevation levels.

## WordPress mapping and implementation notes

- `theme.json` remains the source for WordPress presets and editor-facing global styles. CSS should map those presets to reference/system tokens; patterns and styles should consume semantic roles.
- Keep one token source of truth. Avoid raw hex values in component styles and avoid parallel utility or alias catalogs.
- Keep the light scheme active. A future dark scheme may remap system tokens without changing the reference palette; do not define dark values, automatic detection, or a theme switch in this foundation.
- This document sets the intended architecture only. Implementation files and component specifications are explicitly deferred.
