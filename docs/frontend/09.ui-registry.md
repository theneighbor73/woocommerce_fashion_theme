# UI Registry

This is the source of truth for page, template, and shared-component specifications, including the header. Project purpose and scope decisions are in the [Project Overview](../00.project-overview.md), implementation boundaries are in [Technical Constraints](../constraints/05.technical-constraints.md), and approved design values are in [UI Tokens](08.ui-tokens.md).

## Statuses

- `SPECIFICATION_PENDING` — scope is inventoried but one or more owner decisions are needed before implementation.
- `SPECIFIED` — visual structure, content, editing, native behavior, responsive states, and accessibility requirements are defined; implementation may begin.
- `IN_PROGRESS` — implementation is underway.
- `IMPLEMENTED` — code is complete; ready for runtime review & manual Site Editor review.
- `ESTABLISHED` — passed all reviews, and is now an established feature.

Do not start an element marked `SPECIFICATION_PENDING`. Do not create custom blocks, business behavior, persistent data, or external integrations. Escalate requirements outside that boundary under the [Custom Block Consideration List](../consideration-list.md).

## Shared controls

### Button components — `IMPLEMENTED`

These shared button variants follow [Component states](design-system-reference.html#component-states) and use the approved values in [UI Tokens](08.ui-tokens.md). Use native WordPress/WooCommerce blocks and controls; this specification defines presentation, not new behavior.

- **Semantics:** use links for navigation and buttons for actions, regardless of visual variant. Preserve the native element and behavior provided by the relevant block or control.
- **Variants:** Primary is the square, dark-filled action with inverse text. Secondary is the square, transparent action with a dark outline. WordPress Fill is the rounded Primary counterpart; WordPress Outline is the rounded Secondary counterpart. Both retain their paired variant's colors and state behavior. Do not register separate theme styles that duplicate Fill or Outline. Text and Compact are not shared variants; icon-only controls remain with native icon-capable components and require an accessible name.
- **Sizing and shape:** all four variants use `--control-height-base` (`3rem`) and `--button-padding-x`. Primary and Secondary use square corners; Fill and Outline use `--radius-sm` (`3px`).
- **States:** Primary/Fill rest dark-filled with light text, then invert to a Canvas surface with Primary text on hover and press. Secondary/Outline rest transparent/light with dark text and border, then invert to a Primary surface with inverse text on hover and press. Active states add a pressed cue; Focus remains visible and unobscured; native Disabled and Loading behavior is preserved. State changes must not rely on color alone.
- **Responsive and editing:** variants remain usable across compact, medium, and expanded widths, with labels readable and controls operable at narrow widths. The styles are registered on the native core Button block and appear in its Styles panel; merchants can change labels, destinations, and variants where the block allows it.
- **Accessibility:** target WCAG 2.2 AA; preserve keyboard operation and semantics, visible focus, adequate contrast, and accessible names for icon-only controls. Do not add custom asynchronous behavior.
- **Color:** use the existing inverse surface/text pairs documented in [UI Tokens](08.ui-tokens.md) for hover and pressed states; check text and boundary contrast on actual surfaces.

### Navigation controls — `IMPLEMENTED`

- Navigation links and the mobile menu trigger follow the shared component-state rules in the Design System. The menu trigger uses the native Navigation block's accessible name, keyboard behavior, and open/closed semantics; document only any visual or state exception specific to the header in the Site header entry.
- Navigation destinations remain links. Active/current destination indication must remain perceivable without color alone and must not replace visible keyboard focus.

## Shared shell

### Foundational WordPress content templates — `IMPLEMENTED`

- **Templates:** required `index.html` fallback plus basic `page.html` and `single.html` rendering so general WordPress content remains available during theme setup.
- **Structure:** archive fallback shows a native query loop with featured image, linked title, excerpt, and pagination. Page and single templates show the native title, optional featured image, and full post content in the readable content width.
- **Editing and behavior:** content remains merchant-managed in WordPress; no pages or posts are created by the theme. The templates do not add editorial or business behavior.
- **Phase 3 refinement:** complete the editorial hierarchy, metadata, and responsive specifications before adding richer archive, search, 404, and article treatments.

### Site header — `SPECIFIED`

- **Structure:** preserve the logo, product search, and navigation/account/cart regions, aligned to the shared Space and Layout grid. Reflow or wrap regions as available width requires; do not force three equal columns at compact widths. The native Navigation block becomes a hamburger in compact. The header slides out while scrolling down and reappears while scrolling up at all widths. Use native WooCommerce account/cart icons; do not create theme-authored icon artwork.
- **Data/content:** merchant Site Logo and navigation; native search and WooCommerce account/cart destinations. If no Site Logo is configured, the frontend displays `assets/images/logo/fallback-site-logo.png` linked to the homepage with the site name as its accessible text. A merchant Site Logo always takes precedence.
- **Editing:** merchants can upload or replace the logo and edit navigation contents through native WordPress tools; the semantic regions and order remain fixed while their arrangement may reflow to the grid. With no merchant logo, the Site Editor retains the native Site Logo upload placeholder.
- **Site icon:** WordPress uses `assets/images/site-icon/fallback-favicon.png` when the merchant has not configured a Site Icon. A merchant Site Icon always takes precedence.
- **Behavior:** preserve core Navigation/Search and WooCommerce destination behavior. The hamburger opens a left-side temporary native navigation pane, sized to available width and capped at `24rem`; it has a backdrop, traps focus while open, and dismisses on Escape. Compact panes are temporary; any future fixed pane is limited to expanded or an explicitly specified medium layout. Apply the shared safe-area and z-index rules. The toast region anchors to the top-bar section, layers above panes, and does not permanently block primary controls. Keep the sticky top bar within the compact/short-landscape height cap and accessible at 200% text zoom. Scroll-direction visibility is visual only and progressively enhanced.
- **States:** scroll direction, compact/medium/expanded header and open/closed menu, focus, active/current navigation, and absent optional destinations.
- **Accessibility:** WCAG 2.2 AA target; keyboard operation, visible/unobscured focus, meaningful labels, semantic landmarks, reduced motion.
- **Reference:** `/docs/reference/mobile-homepage.png` for mobile header arrangement only; the mobile header specification above takes precedence where the reference differs.

### Site footer — `IMPLEMENTED`

- **Structure:** fixed footer composition using native blocks and navigation, with editable link groups, contact details, native Social Links, and a bottom legal-link row. Apply the dark background and light text through native block color settings so they are visible in the Site Editor; use CSS only for component-specific layout and responsive details.
- **Content:** use the replaceable tagline “Thoughtful silhouettes and considered details for everyday dressing,” sample address “123 Example Street, Example City, EX 00000,” and `hello@example.com`. Include native Instagram, Facebook, and Pinterest Social Links with `example.com` placeholder URLs. Merchants can replace all placeholder copy and links. Footer navigation links use merchant-configured pages/categories. No newsletter signup, cookie manager, wishlist, promotional ticker, or third-party service feature.
- **Editing:** intended text, media, and navigation are editable; structural arrangement is fixed.
- **Behavior/states:** native links only; responsive stacking and keyboard/focus states.
- **Reference:** `/docs/reference/desktop-footer.png` and `/docs/reference/mobile-footer.png` for broad grouping and responsive stacking only. Excluded features listed above remain out of scope.

## Core shopping experience

### Editorial hero image gallery — `SPECIFIED`

- **Structure:** `front-page.html` inserts the reusable pattern directly below the header. The pattern provides a full-bleed hero frame with a native Gallery image collection and one shared text/button overlay. The image may extend to `100vw`; overlay copy and CTAs stay aligned to the shared grid margin ruler and respect safe-area insets. The rest of the homepage, including the WooCommerce product collection, is deferred.
- **Reuse/inserter:** the composition is the native `alice/editorial-hero-image-gallery` block pattern, titled “Editorial Hero Image Gallery” in the Banner and Call to Action categories. The front-page template uses the same pattern directly below the header. Inserting it into page or post content creates an independent copy that merchants can move, remove, and edit; adjust the heading level to preserve that page's heading hierarchy.
- **Default content:** eyebrow “The new season”; heading “A quieter kind of statement.”; body “Thoughtful silhouettes and considered details for everyday dressing.”; link “Shop the collection.” Merchants can edit the copy and link label/URL.
- **Images and editing:** the Gallery starts with the supplied `desktop-hero-image2.jpg` and `desktop-hero-image1.jpg` examples, using theme asset URLs so images also appear in inserter previews; merchants can replace, add, or remove images. Each slide uses one image with centered `object-position` across breakpoints. There is no per-image crop step; image choice assumes the subject and other essential elements are composed inside a central image-safe region that remains visible in compact portrait crops. The project owner confirmed these examples are owner-created or rights-cleared and approved for theme distribution; see the [Media Asset Inventory](../media-assets.md).
- **Overlay editing:** the text/button Group and its blocks cannot be moved or removed; their content remains editable. The eyebrow, heading, and paragraphs default to the theme Canvas text color; button text uses the existing button color preset. Native Group style choices provide top-left, top-right, center-left, center-right, bottom-left, and bottom-right placements, visible in both editor and frontend. A separate, optional native tint Group is included by default and can be removed by the merchant.
- **CTA presentation:** use the shared Primary button style with no box or text shadow on its label; hero copy keeps its shadow for contrast over imagery.
- **Button variant:** the CTA uses the shared Primary style without a hero-specific color exception.
- **Behavior:** each pattern instance with two or more Gallery images progressively enhances into a pinned scroll sequence. Each image occupies about one viewport interval; scrolling changes to the next or previous image at about 95% of the interval so it stays on screen longer before changing. The final image remains pinned through its interval before normal page scrolling resumes. Multiple component instances on a page keep independent slide positions. A one-image Gallery remains static. Without JavaScript, Gallery images and text/link content remain available. No autoplay or next/previous controls.
- **Accessibility/responsive:** preserve meaningful image alt text, a single level-one heading, visible keyboard focus on the link, safe-area insets on overlay controls, the centered image-safe crop across compact/medium/expanded widths, and reduced-motion behavior. Review with photos whose key content remains inside the center image-safe region at portrait and landscape ratios.
- **Activation:** no pages or other database records are created. The hero is the only Phase 2 homepage deliverable; product/catalog and other commerce templates remain deferred.

### Catalog and product archives — `SPECIFICATION_PENDING`

- **Templates:** shop/catalog, product category, product tag, and applicable archive templates.
- **Content/data:** native WooCommerce product collection/query output: image, name, price/sale price, and native availability labels where provided.

- **Behavior:** native WooCommerce variation, quantity, add-to-cart, validation, reviews when enabled, and related-product behavior when supplied by the approved native template.
- **Editing:** product information remains managed in WooCommerce; template structure is fixed.
- **States:** simple and variable products, unavailable/out-of-stock products, sale pricing, invalid/missing variation selection, mobile gallery, focus, and feedback.
- **Before `SPECIFIED`:** approve section order, gallery behavior/presentation, and related-product inclusion.

### Product search — `SPECIFICATION_PENDING`

- **Behavior/states:** normal results, empty results, keyboard submission, responsive result grid, focus, and clear search context.
- **Editing:** product data stays in WooCommerce; template composition is fixed.
- **Before `SPECIFIED`:** approve search placement and whether results share the catalog card/grid treatment.
