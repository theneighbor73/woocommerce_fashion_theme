# UI Registry

This is the source of truth for page, template, and shared-component specifications. The build sequence is in the [Build Plan](01.build-plan.md); platform, scope, and palette decisions are in the [Project Overview](../00.project-overview.md).

## Statuses

- `SPECIFICATION_PENDING` — scope is inventoried but one or more owner decisions are needed before implementation.
- `SPECIFIED` — visual structure, content, editing, native behavior, responsive states, and accessibility requirements are defined; implementation may begin.
- `IN_PROGRESS` — implementation is underway.
- `IMPLEMENTED` — code is complete; runtime/editor review is tracked separately in the Project Tracker.

Do not start an element marked `SPECIFICATION_PENDING`. Do not create custom blocks, business behavior, persistent data, or external integrations. Escalate requirements outside that boundary under the [Custom Block Consideration List](../consideration-list.md).

## Shared shell

### Foundational WordPress content templates — `IMPLEMENTED`

- **Templates:** required `index.html` fallback plus basic `page.html` and `single.html` rendering so general WordPress content remains available during theme setup.
- **Structure:** archive fallback shows a native query loop with featured image, linked title, excerpt, and pagination. Page and single templates show the native title, optional featured image, and full post content in the readable content width.
- **Editing and behavior:** content remains merchant-managed in WordPress; no pages or posts are created by the theme. The templates do not add editorial or business behavior.
- **Phase 3 refinement:** complete the editorial hierarchy, metadata, and responsive specifications before adding richer archive, search, 404, and article treatments.

### Site header — `IMPLEMENTED`

- **Structure:** fixed composition. Desktop: site logo left, primary navigation right, with native search, account, and cart controls. Mobile: logo and hamburger at left, search centered, account and cart at right. Keep the header fixed while scrolling on mobile; on desktop it slides out while scrolling down and reappears while scrolling up.
- **Data/content:** site logo and merchant-created navigation; native search and WooCommerce account/cart destinations.
- **Editing:** logo and navigation contents are editable with native WordPress tools; merchants cannot rearrange the header composition.
- **Behavior:** preserve core Navigation/Search and WooCommerce destination behavior. The hamburger opens a left-side native navigation panel, about one third of viewport width, with a `16rem` minimum and `24rem` maximum. Any menu and desktop scroll-direction enhancement is visual only and progressively enhanced.
- **States:** desktop scroll direction, tablet, mobile fixed header and open/closed menu, focus, active/current navigation, and absent optional destinations.
- **Accessibility:** WCAG 2.2 AA target; keyboard operation, visible/unobscured focus, meaningful labels, semantic landmarks, reduced motion.
- **Reference:** `/docs/reference/mobile-homepage.png` for mobile header arrangement only; the mobile header specification above takes precedence where the reference differs.

### Site footer — `IMPLEMENTED`

- **Structure:** fixed footer composition using native blocks and navigation, with editable link groups, merchant-provided business/contact details, and a bottom legal-link row.
- **Content:** merchant site identity and links to merchant-configured pages/categories. Merchant-managed social links are allowed. No newsletter signup, cookie manager, wishlist, promotional ticker, or third-party service feature.
- **Editing:** intended text, media, and navigation are editable; structural arrangement is fixed.
- **Behavior/states:** native links only; responsive stacking and keyboard/focus states.
- **Reference:** `/docs/reference/desktop-footer.png` and `/docs/reference/mobile-footer.png` for broad grouping and responsive density only. Excluded features listed above remain out of scope.

## Core shopping experience

### Homepage — `SPECIFICATION_PENDING`

- **Structure:** prebuilt `front-page.html` native-block composition: split editorial hero with text at left and image at right on desktop; full-width portrait hero with text over the image on mobile; followed by a native WooCommerce product collection. Keep section composition fixed.
- **Default copy:** eyebrow “The new season”; heading “A quieter kind of statement.”; body “Thoughtful silhouettes and considered details for everyday dressing.”; link “Shop the collection”; product section heading “Selected for the season.” Copy is editable and makes no time-sensitive offer or product claim.
- **Images:** initial desktop hero candidate: `assets/images/desktop-hero-image2.jpg` (1102 × 734, landscape); alternate: `desktop-hero-image1.jpg` (735 × 488). Initial mobile hero candidate: `3f48d666a9f06eade847c873c96781ac.jpg` (1200 × 1800, portrait). `a00c217222911a9526ce3566b694b5f4.jpg` and `7257653ad7e5d8035e29e59bfe50697f.jpg` are smaller supporting-image candidates. Use these assets for the initial visual build and review crop/resolution in context; replace them if needed after review. Record source, license, and use terms for all bundled images before release. Product collection images come from WooCommerce and use the 3:4 product-image ratio in UI Tokens.
- **Content/data:** collection reads the merchant’s existing catalog. Show a useful empty state when no products exist.
- **Activation:** do not create pages, products, or other database records. Bundle editable theme image assets; record each asset’s source, license, and usage terms in this entry before shipping it.
- **Behavior/states:** native links and product collection only; cover default, empty-catalog, responsive, focus, and reduced-motion states.
- **Before `SPECIFIED`:** review the initial hero asset/crop in the visual build; record image source, license, and usage terms; apply approved design tokens.

### Catalog and product archives — `SPECIFICATION_PENDING`

- **Templates:** shop/catalog, product category, product tag, and applicable archive templates.
- **Content/data:** native WooCommerce product collection/query output: image, name, price/sale price, and native availability labels where provided.
- **Behavior:** native pagination, ordering, and filtering only where supplied by supported WooCommerce blocks/setup. Do not add custom filtering or Store API behavior.
- **Editing:** template composition remains fixed; merchant manages products and taxonomy data in WooCommerce.
- **States:** populated and empty results, sale/unavailable products, responsive columns, keyboard and focus.
- **Before `SPECIFIED`:** approve grid columns, image ratio/crop, card content order, and native filter/sort presentation.

### Product detail — `SPECIFICATION_PENDING`

- **Content/data:** WooCommerce product title, media/gallery, price/sale, description, availability, and supported product-type controls.
- **Behavior:** native WooCommerce variation, quantity, add-to-cart, validation, reviews when enabled, and related-product behavior when supplied by the approved native template.
- **Editing:** product information remains managed in WooCommerce; template structure is fixed.
- **States:** simple and variable products, unavailable/out-of-stock products, sale pricing, invalid/missing variation selection, mobile gallery, focus, and feedback.
- **Before `SPECIFIED`:** approve section order, gallery behavior/presentation, and related-product inclusion.

### Product search — `SPECIFICATION_PENDING`

- **Structure/content:** native WordPress/WooCommerce search control and results presentation for products; no custom live-search overlay.
- **Behavior/states:** normal results, empty results, keyboard submission, responsive result grid, focus, and clear search context.
- **Editing:** product data stays in WooCommerce; template composition is fixed.
- **Before `SPECIFIED`:** approve search placement and whether results share the catalog card/grid treatment.

### Cart — `SPECIFICATION_PENDING`

- **Modes:** WooCommerce Cart block and classic shortcode-backed Cart page.
- **Behavior/data:** preserve native item editing/removal, quantity updates, totals, notices, and checkout navigation for each mode.
- **Editing:** merchant-assigned page and its native WooCommerce mode remain intact; theme styles presentation only.
- **States:** empty/populated cart, changed quantity, removed item, notices, mobile layout, keyboard/focus.
- **Before `SPECIFIED`:** approve presentation differences, if any, between the two native modes.

### Checkout — `SPECIFICATION_PENDING`

- **Modes:** WooCommerce Checkout block and classic shortcode-backed Checkout page.
- **Behavior/data:** preserve native fields, shipping/payment choices, validation, order review, processing, and confirmation. Do not implement payment or order logic.
- **Editing:** merchant-assigned page and its native mode remain intact; theme styles presentation only.
- **States:** valid form, validation errors, processing, gateway unavailable/failure feedback, confirmation, mobile, keyboard/focus.
- **Before `SPECIFIED`:** approve presentation differences, if any, between the two native modes. QA uses a non-production test gateway.

### My Account — `SPECIFICATION_PENDING`

- **Content/data:** WooCommerce native account page and endpoints (login, dashboard, orders, addresses, account details).
- **Behavior:** preserve authentication, forms, endpoints, and notices.
- **Editing/states:** merchant assigns the account page; theme controls fixed presentation. Cover logged-out, dashboard/endpoint, form error/success, mobile, and keyboard/focus states.
- **Before `SPECIFIED`:** approve account navigation layout and endpoint presentation.
