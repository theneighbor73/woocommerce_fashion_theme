Material 3 foundations · light scheme

Quiet clarity, considered detail.

Alice is a minimalist, lifestyle-editorial WordPress block theme for fashion stores. Its foundations use Material 3’s semantic roles and token relationships, expressed through Alice’s own palette, typography, and restrained visual direction. This reference documents foundations only; components are specified separately.

Editorial, restrained, clear

Visual direction & imagery

Use a quiet visual foundation that lets products, useful information, and merchant-provided photography lead.

Composition

  • Keep hierarchy clear and product information easy to scan.
  • Use intentional whitespace and strong editorial compositions.
  • Use asymmetry, split imagery, and alternating compositions selectively instead of repeating one layout everywhere.
  • Keep product cards clean and consistent, with prominent imagery and readable names and prices.

Media

  • Choose image framing for its context. Product imagery uses the documented 3:4 aspect ratio where applicable; editorial frames follow their UI specification.
  • Use cover cropping only when essential subject details remain visible across supported viewport sizes and specified safe areas.
  • Preserve merchant-provided media files; use native blocks and CSS for display size, position, and crop.
  • Use meaningful alt text for informative images and avoid redundant spoken content for decorative images.

Decoration

Use subtle borders and restrained decoration. Avoid generic boxed layouts, excessive shadows, or decorative rounding. Product and lifestyle photography should lead where supplied.

Role boundaries

Accent gold is expressive emphasis, not a default text color on canvas. Outline-variant is a quiet divider; essential control boundaries need a stronger role or treatment. Status meaning must include a clear text or shape cue.

The colors documented in UI Tokens are the approved palette for the current light scheme. Verify foreground/background contrast for actual pairings against WCAG 2.2 AA. Surface containers are optional neutral hierarchy levels; use only the levels a real layout needs.

The approved palette supports the current light scheme. Adding or changing a color requires project-owner approval and documentation in both UI Tokens and Design Foundations, including its semantic role and verified contrast pairings. Keep the system-token structure extensible for a future dark-mode switch; additional reference colors may be approved if that mode needs them. No dark-mode values or behavior are defined now.

Adaptive foundation

Space & layout

Alice uses three width classes, one low-density level, and intrinsic reflow. The same universal rulers guide templates, reusable components, and full-bleed editorial moments.

This foundation is LTR only. Component specifications use left/right and top/bottom terms; do not add RTL mirroring rules or logical-property abstractions.

The classes adapt the grid and its margins; they do not identify a device or guarantee reflow by themselves. Content must still shrink, wrap, and fit within the available space.

Pointer, touch, and click

Interaction

Every input method can reach essential actions and information. Preserve native WordPress and WooCommerce behavior; these rules describe the expected presentation and interaction model.

Desktop · click and hover

Click activates standard controls and toggles expandable menus. Pointer hover may reveal a subtle visual state or desktop dropdown. Hover never carries essential information by itself.

Use brief, token-based feedback and preserve foreground/surface contrast.

Mobile · tap and touch

Ordinary buttons and links act on the first tap. For a parent item with a submenu, the first tap expands/folds the submenu; after a pause, a subsequent tap toggles/folds it, while a double tap navigates to the parent destination.

There is no mobile hover state. Keep submenu expansion and parent navigation clearly named and operable by keyboard and assistive technology.

Do not rely on hover alone to reveal controls or information. Preserve native link, navigation, form, and commerce semantics; this model does not add behavior.

Purposeful feedback

Motion & accessibility

Motion supports orientation and state feedback. It should be brief, consistent, and unnecessary for understanding content or completing a task.

Duration is elapsed time

Each marker travels from the shared start to its endpoint; its arrival shows when that duration finishes. The ruler is 0–600ms.

Duration answers “how long?” Easing describes how progress changes during that time. Alice uses --md-sys-motion-duration-fast, standard, and long.

Alice’s standard editorial curve starts quickly, then slows into its endpoint. The marker follows the curve to show that pacing; it does not overshoot or spring.

Accessibility foundation

Target WCAG 2.2 AA for theme-authored presentation. Verify text and non-text contrast on actual pairings, keep focus visible and unobscured, and do not communicate meaning by color alone. Preserve keyboard access, semantic hierarchy, and accessible names for icon-only controls across compact, medium, and expanded widths. Review native WooCommerce controls for styling regressions without claiming ownership of plugin markup.

Honor prefers-reduced-motion by removing nonessential movement and smooth scrolling.

Keep the Site Editor close to the frontend so merchants can understand and customize what they will publish. Set meaningful block-level presentation in native attributes or theme.json where practical; use CSS for responsive behavior and component details that are awkward or unavailable in native controls. Prioritize parity for structure, colors, spacing, and visible states over exact pixel matching.
