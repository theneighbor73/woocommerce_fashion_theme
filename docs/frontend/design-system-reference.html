At a glance

Decision status

“Approved” means the token or shared rule is explicitly documented. “Specified with open details” means the direction exists but still needs supporting detail or review. “Missing or pending” marks a gap or a UI Registry area awaiting its own specification.

Approved

Color roles and named values; type families and scale; spacing, widths, and breakpoints; control and radius values; shadow and layer tokens; shared component states; broad media and accessibility rules.

Specified with open details

Shade ramps have an approved algorithm and WordPress preset naming pattern, but the documentation does not enumerate each ramp’s base slug and sRGB value. Motion tokens exist, while component-by-component timing and easing assignments are not mapped.

Missing or pending

Several catalog, product, search, cart, checkout, and account presentations remain SPECIFICATION_PENDING in the UI Registry. Their component-specific decisions are not implied by this artifact.

Source boundary

Values here come from project documentation. This page does not inspect or reproduce theme.json, current CSS, templates, or the live site.

00 · Visual direction

Editorial, useful, unforced

The system aims for minimalist contemporary fashion with a lifestyle-editorial feel. The specimen layout is only one possible composition; the documented principles allow variety while keeping product information easy to scan.

Composition principles

  • Keep hierarchy clear and product details easy to scan.
  • Use intentional whitespace and strong editorial compositions.
  • Use asymmetry, split imagery, and alternating layouts selectively rather than repeating one formula.
  • Keep product cards clean, with prominent imagery and readable name and price.

Media framing

  • Let lifestyle and product photography lead; preserve merchant files unchanged.
  • Use the 3:4 product image ratio where applicable; editorial frames follow their own UI specification.
  • Cover-crop only when essential subject details remain visible at supported sizes and safe areas are respected.
  • For the specified hero, center the image and keep key content inside the central safe area through portrait mobile cropping.

Prefer subtle borders and restrained decoration. Avoid generic boxed layouts, excessive shadows, and decorative rounding. The panels in this reference are catalog specimens for readability, not a mandate to box storefront sections.

Documented contrast notes

Muted text: 5.41:1 against Canvas. Success: 5.98:1 against Canvas. Primary accent: 2.32:1 against Canvas, so reserve it there for decorative emphasis; 7.69:1 against the dark primary surface. Check all actual pairs against WCAG 2.2 AA.

Nine-step ramp rule

Existing palette color/slug is step 500. Added preset names follow {base-slug}-{step}: 100–400 blend base with white; 600–900 blend base with black. The docs do not list all base slugs and resulting values, so no unverified ramp chips are fabricated here.

06 · Motion

A restrained motion vocabulary

Token names and values are approved. Reduced motion must be respected. The exact mapping from duration/easing to each component transition remains a documentation opportunity, except where specific behavior is described in the UI Registry.

Timing and easing tokens

--ease-editorial: cubic-bezier(0.22, 1, 0.36, 1)

--duration-fast: 200ms · --duration-base: 350ms · --duration-media: 600ms

Static illustration of transition length, not an animated sample.

Documented interaction examples

  • Button press may add a small positional cue while preserving color pairing.
  • Homepage gallery with multiple images progressively enhances to a pinned scroll sequence; changes near 95% of each viewport interval.
  • Header hides on downward scroll and returns on upward scroll; visual enhancement only.
  • Respect reduced-motion preferences; do not invent motion unsupported by the native interaction.

07 · Icons and assets

Use the merchant’s media and native icons

No theme-authored icon artwork is specified. The documented approach favors native WordPress/WooCommerce icon-capable controls and meaningful accessible names. Color shades may be used for icons, with contrast checked in context.

Icon and media rules

Aa This typographic marker is only a placeholder, not an icon proposal.

  • Use native WooCommerce account/cart icons; do not draw replacements.
  • Icon-only controls need accessible names.
  • Use merchant media as supplied; do not modify source files.
  • Meaningful images need useful alt text; decorative images should avoid redundant spoken content.

09 · Open work

Where the system still needs decisions

These items are visible in the documentation as missing details or pending UI specifications. This list is an aid to review, not a new source of design decisions.

  • Specified with open detailsList the base palette slugs and each static sRGB shade value (the naming/derivation rule is already documented).
  • Specified with open detailsMap motion tokens to component transitions where the registry needs those specifics; document reduced-motion presentation for each relevant interaction.
  • Specified with open detailsClarify the complete iconography policy beyond native account/cart and native Social Links; do not infer custom icon assets.
  • Specified with open detailsConsider documenting elevation/layer usage examples and assignments if components require more than the current floating-layer guidance and token scale.
  • Missing or pendingCatalog/archive UI: approve grid, crop, card order, and native filter/sort presentation.
  • Missing or pendingProduct detail: approve section order, gallery presentation, and related products.
  • Missing or pendingProduct search: approve placement and whether it shares catalog grid treatment.
  • Missing or pendingCart and checkout: resolve any presentation differences between native block and classic modes.
  • Missing or pendingMy Account: approve account navigation layout and endpoint presentation.
  • Missing or pendingEditorial pages, archives, search fallback, and 404: define hierarchy, editable regions, locking, responsive behavior, and accessibility before implementation.
